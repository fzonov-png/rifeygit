# RifeyGit — статическая версия (GitHub Pages)

Постоянная ссылка: `https://fzonov-png.github.io/rifeygit/`
Работает 24/7 с телефона в любой сети: нет сервера, нет VPS, нет установок.
Данные (программы, версии, схемы, реестр, пользователи) — в этом репозитории.

## Страницы

* `login.html` — отдельная страница входа. Без входа главная не открывается.
* `index.html` + `app.js` — главная после входа: «Скачать», «Программы и
  схемы», «Реестр», «Пользователи» (роли admin/engineer).
* `tools/upload.html` — страница инженера: загрузка версий ПЛК, панелей,
  схем и создание пользователей. Доступна только admin/engineer и требует
  GitHub-токен.
* `zip.js` — собственный сборщик ZIP (без внешних CDN), чтобы комплектные
  архивы собирались даже при недоступности сторонних библиотек.

## Модель данных

Одна версия программы ПЛК может иметь несколько версий программы панели:

```json
program.versions[] = {
  "version": "3.2", "pult": "ПУ-БЗ", "message": "…", "author": "…",
  "plc": { "path": "data/files/…", "name": "fw.ap15", "size": 12345 },
  "panels": [
    { "version": "1.0", "hmi_type": "ПУ-БЗ", "message": "…",
      "file": { "path": "…", "name": "panel.emtp", "size": 1234 },
      "kit":  { "path": "…", "name": "BZ120_3.2_1.0_ПУ-БЗ.zip", "size": 4321 } }
  ]
}
```

Схемы привязаны к пульту (и, необязательно, к программе): к одному пульту
можно добавить сколько угодно схем — они все попадают в комплектный архив
`<код>_<версия ПЛК>_<версия панели>_<пульт>.zip`.

Старый формат (`files: {plc, hmi, kit}`) читается автоматически — старые
версии остаются доступными.

## Как устроены данные

* `data/site.json` — программы, версии, схемы, реестр оборудования.
* `data/users.json` — пользователи: логин, роль, **солёный хэш SHA-256**
  (пароли открытым текстом нигде не хранятся).
* `data/files/…` — программы ПЛК/панелей, комплектные архивы, схемы.

Запись идёт через GitHub API одним коммитом. Повторная попытка при
конкурентном коммите выполняется автоматически (перечитывается HEAD ветки).

## Важно про доступ

* Опубликованный сайт и все файлы в нём **доступны по ссылке** (так устроен
  GitHub Pages — сайт публичный). Пароль защищает от случайных посетителей,
  но не является крепкой защитой: не храните в системе секретов.
* Токен инженера (fine-grained, **Contents: Read and write** на этот
  репозиторий) вставляется один раз в `tools/upload.html` и хранится только в
  localStorage браузера — в репозиторий он не попадает.
* Скачивание наладчиком требует заводской № объекта и назначение; журнал
  скачиваний ведётся на устройстве и отправляется отчётом в WhatsApp.
* История git = журнал и бэкап: любую версию данных можно вернуть
  (Settings → Commits → Browse files → нужный коммит → Restore).

## Обновление сайта

```powershell
$env:GITHUB_TOKEN = '<токен>'
python deploy/pages-deploy.py
```

Скрипт заливает `pages/` одним коммитом и **не перезаписывает живые**
`data/site.json` и `data/users.json`. Сбросить их к локальной пустой версии
можно только явно: `python deploy/pages-deploy.py --reset-data`.

После коммита GitHub Pages пересобирает сайт за 1–10 минут. Главная страница
читает `site.json` через API (свежие данные сразу), при исчерпании лимита API —
через CDN, при отсутствии сети — из локальной копии.

## Наполнение из старой базы

```powershell
python deploy/fetch-data.py     # выгрузка с VPS по SFTP
python deploy/pages-import.py   # импорт в новую модель
python deploy/pages-deploy.py   # публикация
```
